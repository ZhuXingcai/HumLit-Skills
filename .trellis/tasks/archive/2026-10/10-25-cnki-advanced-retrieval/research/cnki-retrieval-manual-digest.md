# 知网检索官方手册要点摘录（层 1 文档的权威依据）

来源：
- 主手册（用户提供）：https://piccache.cnki.net/index/helper/manuals.html#frame2-1-2
  章节 1.2.1 一框式检索、1.2.2 高级检索、1.2.5 专业检索、1.3.4 检索条件显示、1.3.6 检索历史
- 交叉核对：https://picx.cnki.net/kdn/index/helper/manual.html （快报 2.0 简易操作说明，1.2.5 专业检索）

以下为手册事实，不是本项目推断。写入 skill 文档时必须保持语义一致。

## 1. 一框式检索也支持同字段组合运算（对方案影响最大）

一框式与高级检索均支持在同一检索项内使用：

| 符号 | 含义 |
|------|------|
| `*` | 与，同时包含 |
| `+` | 或，包含其一 |
| `-` | 非，包含前者但不包含后者 |

规则：
- 输入 `*`、`+`、`-` 时**前后要空一个字节**。
- 检索框输入内容**不得超过 120 个字符**。
- 检索词本身含空格，或含 `*`、`+`、`-`、`()`、`/`、`%`、`=` 等特殊符号时，
  多词组合运算须用**英文半角单引号或双引号**括起。
- 英文半角括号 `()` 用于确定优先级。

手册原文示例：
- `篇名：神经网络 * 自然语言`
- `主题：(锻造 + 自由锻) * 裂纹`
- `篇名：'digital library' * 'information service'`
- `篇名：'2+3' * 人才培养`

推论（本项目方案依据）：表达"A 且 B 且 C"**不必强行走专业检索**，
一框式/高级检索的同字段组合即可覆盖大量场景；CLI 需要做的是把表达式
按上述空格/引号规范传入，而不是继续把空格分隔的长串词当作一个检索词。

## 2. 高级检索的硬约束

- 检索条件输入区默认三行：**主题、作者、文献来源**。
- 可增删检索项，**最多支持 10 个检索项组合**。
- **多字段组合检索的运算优先级，按检索条件从上到下的顺序依次进行**
  （不是常规布尔优先级；设计条件顺序时不能假设 AND 优先于 OR）。
- 检索控制区：出版模式、基金文献、时间范围、检索扩展。
- **检索时默认进行中英文扩展**，不需要时须手动取消勾选。
  → 这是中文精准检索混入大量英文结果的一个明确来源，CLI/文档必须可控制。
- 高级检索页可切换标签：高级检索 / 专业检索 / 作者发文检索 / 句子检索。
- 总库高级检索提供 **168 专题导航**（基于中图分类的学科分类体系）。

## 3. 匹配方式（高级检索 1.2.2.8）

- **主题只提供相关度匹配**，没有精确/模糊可选。
- 其他检索项提供精确、模糊两种，且**含义按检索项分两类**：

| 检索项类别 | 精确匹配 | 模糊匹配 |
|---|---|---|
| 篇关摘（篇名与摘要部分）、篇名、摘要、全文、小标题、参考文献 | 检索词作为整体匹配，结果须完整包含检索词 | 对检索词分词后在相应检索项中匹配 |
| 篇关摘（关键词部分）、关键词、作者、机构、基金、分类号、文献来源、DOI | 对应字段值与检索词**完全一致** | 对应字段值**包含**检索词 |

→ "精确"在关键词/作者/来源类字段上是**完全一致**，比篇名类的"整体包含"更严。
写文档时必须区分，不能笼统说"精确=更准"。

## 4. 词频选择（1.2.2.9）

仅针对**全文和摘要**检索：结果须同时满足包含检索词，且检索词出现次数 ≥ 所选词频。

## 5. 结果中检索（1.2.2.11）

- 支持在上一次结果范围内继续检索；新条件显示在结果区上方。
- 新条件与之前的条件用 **AND** 连接。
- 示例：先检索主题"人工智能"，再在结果中检索主题"机器人"。

→ 这是"先宽后窄、每次只加一个条件"的原生机制，迭代策略应优先用它，
而不是每次重写整条检索式。

## 6. 检索推荐/引导（1.2.2.7）

- 主题、篇名、关键词、摘要、全文等内容检索项会推荐**同义词、上下位词、相关词**。
- 推荐显示在页面右侧；勾选后执行检索，结果为**包含原检索词或勾选词的全部文献**。
- 示例：输入"人工智能"可推荐"机器智能""决策系统"。

→ 同义词扩展应优先使用知网自身的推荐引导，而不是让 agent 凭记忆编造同义词。
这直接回应项目"不夸大、不编造"的原则。

## 7. 专业检索（1.2.5）

一般式：`<字段代码><匹配运算符><检索值>`

### 字段代码
SU=主题, TI=题名, KY=关键词, AB=摘要, FT=全文, AU=作者, FI=第一责任人,
RP=通讯作者, AF=机构, JN=文献来源, RF=参考文献, YE=年, FU=基金,
CLC=分类号, SN=ISSN, CN=统一刊号, IB=ISBN, CF=被引频次

### 匹配运算符
| 形式 | 功能 | 适用字段 |
|---|---|---|
| `= 'str'` | 与 str 相等的记录 | KY、AU、FI、RP、JN、AF、FU、CLC、SN、CN、IB、CF |
| `= 'str'` | 包含完整 str 的记录 | TI、AB、FT、RF |
| `% 'str'` | 包含完整 str 的记录 | KY、AU、FI、RP、JN、FU |
| `% 'str'` | 包含 str 及 str 分词的记录 | TI、AB、FT、RF |
| `% 'str'` | 一致匹配或与前面部分串匹配 | CLC |
| `%= 'str'` | 相关匹配 str | SU |

手册建议：**主题检索优先使用相关匹配运算符 `%=`**。
示例：`KY = 数据挖掘`、`AB % 计算机教学`、`SU %= 大数据`。

### 逻辑运算符
`AND` / `OR` / `NOT`，**前后须有空格**；优先级用英文半角圆括号 `()` 确定。
示例：
- `KY = 知识管理 AND AU = 邱均平`
- `SU %= 知识管理 OR TKA = 知识管理`
- `TI = 大数据 NOT TI = 大数据集`
- `AU = 钱伟长 AND (AF = 清华大学 OR AF = 上海大学)`
- `AU = 钱伟长 AND AF = 清华大学 AND (TI = 物理 OR AB = 物理)`

### 复合运算符（字段内）
`*` 并含、`+` 或含、`-` 不含。
示例：`FT = 催化剂 * 反应率`、`KY = 铝合金 + 钛合金`、`KY = 大数据 - 人工智能`。

### 比较运算符
`YE BETWEEN ('2010', '2018')`、`CF > 0`、`CF >= 1`。

### 位置描述符（仅 TI、AB、FT；仅限定同字段内的两个值）
| 描述符 | 功能 |
|---|---|
| `#` | 两词同句 |
| `%` | 两词同句且 STR1 在 STR2 前 |
| `/NEAR N` | 同句且相隔不超过 N 个字词 |
| `/PREV N` | STR1 在前且间隔不超过 N |
| `/AFT N` | STR1 在 STR2 后（手册定义与示例不一致，见下） |
| `/SEN N` | 同段且句子序号差不大于 N |
| `/PRG N` | 相隔不超过 N 段 |
| `$ N` | 检索词最少出现 N 次 |

须用一组英文半角单引号把检索值及其运算符括起。
示例：`FT = '人工智能 # 推荐算法'`、`FT = '人工智能 /NEAR 10 推荐算法'`、
`FT = '出版 /PRG 5 法规'`、`FT = '大数据 $5'`。

## 8. 手册自身的不一致（写入 skill 时必须标注，不得当成确定事实）

1. 字段表写 `SN=ISSN`，匹配运算符适用字段里有一处写成 `ISSN`。
2. 逻辑运算符示例用了 `TKA`（篇关摘），但它不在前文正式字段代码表中。
3. `/AFT N` 表格定义写"超过 N 个字词"，示例解释却是"间隔不超过 10 个字词"。

→ 这三处在 skill 文档里标为"手册存疑，需在线验证"，`/AFT N` 不纳入推荐用法。

## 9. 检索条件显示与检索历史（1.3.4 / 1.3.6）

结果页提供"检索条件显示"与"检索历史"。
→ 层 3 的"提交后回读校验"有原生依据：可读结果页的检索条件区，
确认实际执行的条件与请求一致，而不是只看是否返回了结果。
