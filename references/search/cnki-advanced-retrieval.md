# 知网高级检索：检索式构造与精准定位

> 依据知网官方检索手册 1.2.1（一框式）、1.2.2（高级检索）、1.2.5（专业检索）。
> 专业检索的完整语法见 [专业检索表达式语法](./cnki-professional-syntax.md)。
>
> **一句话原则**：一个检索框里塞多个空格分隔的关键词，是最容易失败的用法。
> 先把研究问题拆成若干"概念组"，再明确检索项、逻辑关系和匹配方式。

## 1. 先选检索方式，再写检索式

| 场景 | 方式 | 本项目命令 |
|------|------|-----------|
| 单概念探路 | 一框式（主题） | `search "词"` |
| 多概念需要 AND 组合、需精确/模糊控制 | 高级检索（最多 10 项）/ 同字段组合 | `search "" --condition ...`（可重复） |
| 跨字段布尔、位置限定、年份/被引比较 | 专业检索 | `search "" --professional "表达式"` |
| 若干**并列独立**主题各查一轮 | 批量检索（**不是 AND**） | `batch-search "词1" "词2"` |
| 作者/期刊/机构定向 | 高级检索 | `search "" --author 张三`、`--journal 中国社会科学` |

**关键区分**：`batch-search` 是 N 次独立检索后合并，只扩展覆盖面，
**不能**表达"A 且 B"。需要交集时用高级检索或同字段组合。

## 2. 从研究问题到检索式

### 2.1 拆概念组

1. 拆成 2–4 个必须同时满足的概念块；
2. 每块列同义词、英文对应词、上下位词、常见缩写；
3. 块内"或"、块间"与"，明确排除的概念用"非"。

示例（生成式 AI 广告披露 → 品牌信任）：

| 概念块 | 同义/相关词 |
|--------|------------|
| 生成式 AI 广告 | 生成式AI、生成式人工智能、AIGC、AI生成广告、智能广告 |
| 披露 | 披露、告知、标识、来源提示、透明度 |
| 结果变量（可选） | 品牌信任、消费者信任、广告态度 |

```
主题：('生成式AI + 生成式人工智能 + AIGC') * ('广告 + 营销')
篇名：披露 + 告知 + 标识
```

### 2.2 同义词从哪来（不要凭记忆编）

高级检索页右侧会针对主题/篇名/关键词/摘要/全文推荐**同义词、上下位词、相关词**，
勾选后结果为"含原词或勾选词"的并集。**优先用知网推荐**；
只有推荐缺失时，才从已检文献的关键词字段回收实际用词。
不得凭空构造术语或把近义但不相关的词塞进同一组。

### 2.3 选检索项

| 检索项 | 适用 | 噪声/召回 |
|--------|------|-----------|
| 主题（`SU`） | 探路、概念边界不清 | **只支持相关度匹配**，召回大、噪声大 |
| 篇关摘（`TKA`） | 折中 | 中 |
| 篇名（`TI`） | 精准定位某类研究 | 噪声最小，易漏 |
| 关键词（`KY`） | 作者自陈主题 | 小，受标引习惯影响 |
| 摘要（`AB`）/ 全文（`FT`） | 命中结论、方法，或"文中提过某概念" | 中 / 最大 |
| 作者/第一作者/通讯作者/作者单位/基金 | 定向某人或机构、项目成果 | 严 |
| 参考文献/分类号/小标题/DOI/文献来源 | 引文追踪、学科分类、章节主题、精确到篇、特定期刊 | 严 |

收敛顺序：主题 → 篇关摘 → 篇名/关键词，每步都重看命中数。

### 2.4 选匹配方式

**主题只提供相关度匹配**，没有精确/模糊；给主题指定精确/模糊属用法错误。
其余检索项的"精确/模糊"含义**按检索项分两类**：

| 检索项 | 精确 | 模糊 |
|--------|------|------|
| 篇名、摘要、全文、小标题、参考文献、篇关摘（篇名部分） | 检索词作为**整体**匹配 | 分词后匹配 |
| 关键词、作者、机构、基金、分类号、文献来源、DOI、篇关摘（关键词部分） | 字段值**完全一致** | 字段值**包含**检索词 |

所以关键词/作者/来源上选"精确"是**完全一致**，极易 0 命中，通常应选"模糊"。

## 3. 同字段组合运算（一框式与高级检索都支持）

`*` 与（同时包含）、`+` 或（含其一）、`-` 非（含前者不含后者）。

硬性规则：

1. `*`、`+`、`-` **前后各空一个字节**。`人工智能+AIGC` 是错的。
2. 单个检索框**不超过 120 个字符**，超出请拆条件或改用专业检索。
3. 检索词本身含空格或 `* + - ( ) / % =` 时，用**英文半角引号**括起：
   `'digital library' * 'information service'`、`'2+3' * 人才培养`。
4. 优先级用英文半角括号：`(锻造 + 自由锻) * 裂纹`。

## 4. 高级检索的额外约束

- 默认三行（主题、作者、文献来源），最多 **10 个检索项**。
- **多字段优先级按条件从上到下依次运算**，不是常规布尔优先级。
- 检索控制区含出版模式、基金文献、时间范围、检索扩展。
- **中英文扩展默认开启**，会让中文检索混入英文文献；需要纯净中文用
  `--cross-language off`。
- 结果页支持**结果中检索**，新条件与既有条件用 **AND** 连接——
  这是"先宽后窄"的原生机制，优于每次重写整条检索式。

## 5. 专业检索

字段代码 + 匹配运算符 + 检索值，字段间用 `AND/OR/NOT`（前后须空格），
字段内用 `* + -`，位置描述符仅用于 `TI/AB/FT` 同字段两值之间。

```
SU %= ('生成式AI+生成式人工智能') AND KY % ('广告+营销')
YE BETWEEN ('2020', '2024')
```

完整字段代码、匹配符适用字段、位置描述符含义见
[专业检索表达式语法](./cnki-professional-syntax.md)。

## 6. 迭代策略

1. **先宽后窄**：主题 + 少量概念块看规模，再逐层收窄。
2. **每次只加一个条件**，记住前后命中数，才知道是哪个条件把结果杀到 0。
3. 命中 0 时按序回溯：字段过严 → 匹配方式过严 → 同义组太窄 →
   被 `-` 排除 → 中英文扩展干扰。
4. 命中过多时：换 `TI`/`KY`、加 `NOT`、加年份或核心期刊、用 `/NEAR` 收紧；
   已有可用结果时用**结果中检索**加条件，而不是从头重写。

## 7. 与本项目命令的对照

```bash
# 一框式（单概念探路）
search "生成式AI广告"

# 高级检索：多条件，各自指定逻辑与匹配方式
search "" --condition "篇名|并且|模糊|生成式AI" \
          --condition "关键词|并且|模糊|广告" \
          --condition "摘要|或者|模糊|品牌信任"

# 同字段组合（块内 OR）写在值里，运算符前后必须空格
search "" --condition "篇名|并且|模糊|(生成式AI + AIGC + 智能广告)"

# 专业检索：位置参数留空
search "" --professional "SU %= ('生成式AI+生成式人工智能') AND KY % ('广告+营销')"

# 关闭中英文扩展，只看中文文献
search "信息茧房" --cross-language off
```

`--condition` 三种写法：`字段|值`、`字段|逻辑|值`、`字段|逻辑|匹配|值`。
逻辑 `并且/或者/不含`（亦接受 `AND/OR/NOT`），匹配 `精确/模糊`（亦接受 `exact/fuzzy`）。
字段名：主题、篇关摘、关键词、篇名、全文、作者、第一作者、通讯作者、作者单位、
基金、摘要、小标题、参考文献、分类号、文献来源、DOI。

**`--condition` 实际如何执行**：条件会被编译成专业检索表达式在专业检索页执行，
`retrieval.expression` 即真正提交的检索式，可直接到知网复核。编译映射与括号规则见
[专业检索表达式语法 · 条件编译映射](./cnki-professional-syntax.md#9-条件编译映射)。

### 7.1 输出里的 `retrieval` 必须读

```jsonc
"retrieval": {
  "mode": "advanced",               // simple / advanced / professional / batch / cached
  "requested": {"conditions": []},  // 请求的条件
  "applied":   {"conditions": []},  // 实际应用的条件
  "verified":  true,                // true=回读一致；false=不一致；null=无法回读
  "expression": "TI % 生成式AI AND (KY % 广告 OR AB % 品牌信任)",
  "total_hits": 35                  // 命中数；真实空结果为 0，读不到才为 null
}
```

- `verified: false` 必伴随 `CNKI_RETRIEVAL_MISMATCH`，**结果不可信**。
- `verified: null` 只表示无法回读，不能声称"已核对"。
- `total_hits` 是判断收窄/放宽的唯一依据；`0` 表示已确认真实空结果，`null` 才表示读不到。
  不要用 `null` 推断命中规模。

## 8. 反模式（出现即错）

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| `search "生成式AI 广告 品牌信任"` | 一框塞多概念，0 命中或全噪声 | 拆概念组，用 `--condition` 分字段限定 |
| 把 `batch-search` 当交集 | 批量是独立检索 | `--condition` 或 `--professional` |
| 命中 0 就写"没有相关研究" | 混淆检索失败与真实空结果 | 先查 `source_statuses` 与 `total_hits` |

## 9. 证据边界

- 命中数、核心期刊标记、`retrieval_priority_score` 都**不是**学术质量判断。
- 只有来源状态成功且 `verified` 为真时，空结果才能写成"未检索到"，并须附数据库、
  检索式、时间范围与命中数。检索式是否生效以 `retrieval.applied` 为准，不以"页面能打开"为准。
