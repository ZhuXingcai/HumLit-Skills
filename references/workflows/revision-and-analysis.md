# 文档修订与研究分析工作流

## 在原论文中插入引用（保留格式）

1. `read-paper` 读取论文。
2. 搜索并核对候选文献。
3. 生成补丁 JSON：

```json
{
  "patches": [{"find": "原文片段", "replace": "替换后片段"}],
  "footnotes": [{"after": "定位文本", "text": "脚注引用内容"}],
  "append_references": ["[1] 参考文献1"]
}
```

`find` 和 `after` 至少 10 字且在文档中唯一，尽量不要跨越加粗或斜体边界。

```bash
patch-docx 原论文.docx --patch patch.json --output 修改后.docx
```

## 学术表达优化

当用户请求“降重”“改重”或“降低重复率”时，将任务限定为保原意的学术表达
优化，不检测或承诺相似度数值。

1. `read-paper` 理解结构、论点和论证逻辑。
2. 用 `polish-signals` 定位规则信号。
3. 重点检查照搬定义、直接摘抄、缺少作者分析和过渡薄弱。
4. 通过措辞、句式、原创评述和论证衔接提升表达。
5. 生成 patch JSON，用 `patch-docx` 写回。
6. 报告改动段落、策略和前后对比。

约束：

- 不改变原文学术含义。
- 不删除关键论据。
- 不引入原文未涉及的观点。
- 用户提供标注报告时，以报告定位为主要依据。

## 引文网络分析

```bash
citations "<DOI、URL或arXiv ID>" --direction both
```

- `citing`：后续研究引用了该论文。
- `references`：该论文引用的前人工作。
- 结果依赖 Semantic Scholar 覆盖和配额，不依赖 CNKI。
- 上游限流或缺失不得解释为完整引文网络。

## 研究趋势分析

1. 先确保会话中有搜索或导入数据。
2. 运行 `trends` 获取年份、高频词、高被引线索和来源分布。
3. Agent 只描述当前检索语料，不外推为整个学科的因果趋势。

## 文献对比矩阵

读取实际摘要或全文后，按以下维度比较：

| 维度 | 内容 |
|------|------|
| 研究问题 | 论文试图回答什么 |
| 研究方法 | 定性、定量、混合及具体方法 |
| 数据来源 | 样本量和收集方式 |
| 核心发现 | 主要结论 |
| 理论贡献 | 对已有理论的推进 |
| 局限性 | 作者承认的局限 |
| 与用户研究的关联 | 可支持或启发之处 |

输出可写为 Markdown，再用 `write-docx` 转为 Word。

## 阅读笔记生成

每篇论文使用：

```markdown
## [论文标题]（[年份]）
**作者**：[作者列表]
**期刊**：[期刊名]
**核心论点**：[1-2 句]
**研究方法**：[方法]
**关键发现**：
- [发现 1]
- [发现 2]
**与我的研究的关联**：[关联]
**值得引用的观点**：[页码/章节]
**局限与未来方向**：[局限]
```

多篇论文最后附综合评述，区分共识、分歧和仅基于当前语料观察到的缺口。
